# Первый блок чек-листа: техническая готовность

Источник задач: предоставленный владельцем файл `gemini-code-1790699585452.md`. Этот документ фиксирует только технические изменения первого блока; юридические тексты и платежные интеграции из блоков 2–4 будут согласовываться отдельно.

| Задача | Состояние |
| --- | --- |
| RU / UZ (латиница) / EN и переключатель | Уже работали; новые страницы и сообщения добавлены в словарь, проверяются `pnpm check:locales`. |
| Юридический футер на всех страницах | Добавлен. Ссылки открывают честные страницы-заглушки до утверждения документов. Реквизиты и телефон не выдуманы. |
| Регистрация и согласия | Форма и API готовы. Согласие с правилами обязательно, маркетинговая рассылка отдельно и добровольно, решения сохраняются в БД. До утверждения юридических документов регистрация закрыта двумя серверными флагами. |
| Удаление аккаунта | Пользователь может подать аутентифицированный запрос; он виден суперадмину. Автоматическое удаление данных и учет обязательных сроков хранения требуют согласованной политики и отдельной процедуры. |
| Платные услуги | Стоимость публикации и тарифа фиксирована в UZS даже при USD-переключателе цен недвижимости. Перед отправкой данных о переводе требуется отдельное подтверждение ознакомления с офертой и правилами возврата; до публикации этих документов сервер не принимает платежные заявки. Онлайн-эквайринга пока нет. |
| Cookie и маркетинг | Показан баннер о необходимых cookie. Отдельное согласие на маркетинг предусмотрено при регистрации и в настройках уведомлений. Необязательные трекеры сейчас не подключены. |
| Размещение данных | Docker-стек уже использует PostgreSQL, Redis и S3-совместимое хранилище. Действующий VPS пока не подтвержден как физически размещенный в Узбекистане; перенос не выполнен. |

Для включения регистрации и платных переводов сначала заменить заглушки на утвержденные тексты, внести фактические реквизиты и контакты, проверить полный сценарий, затем настроить `LEGAL_DOCUMENTS_PUBLISHED=yes`. Самостоятельную регистрацию дополнительно включает `ESTATEHUB_SELF_REGISTRATION=enabled`. Эти флаги **не следует** включать с текущими заглушками.

В исходном чек-листе утверждение о необходимости размещения **всей** базы в Узбекистане опирается на старую редакцию закона. Изменения от 26 марта 2026 года к статье 27¹ перечисляют категории данных, подлежащие обязательному хранению в Узбекистане, и условия для обработки остальных данных за рубежом. Нужна отдельная юридическая оценка конкретных данных EstateHub, договоров с провайдером и физических мест хранения. Технически перенос PostgreSQL и приложения на узбекский VPS возможен через существующий Docker Compose, но для этого нужен выбранный хостинг и доступ к нему.

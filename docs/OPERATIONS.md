# EstateHub: данные и восстановление

## Локальный стенд

Из корня репозитория запустить `python3 scripts/backup-local-db.py`. Скрипт снимает согласованную копию локальной D1, проверяет `PRAGMA integrity_check`, восстанавливает копию во временную БД и сверяет количество ключевых записей. Результат сохраняется в игнорируемом Git каталоге `work/backups/` с правами `0600`. Скрипт не меняет исходную БД.

Локальная копия содержит персональные данные. Не прикладывать её к задачам, письмам и коммитам. Для передачи или долгого хранения требуется шифрование и ограниченный доступ.

## Публичная D1 после получения Cloudflare-доступа

1. Узнать имя базы и тип хранилища через `pnpm exec wrangler d1 info <DATABASE>`. Для новой production D1 Cloudflare предоставляет Time Travel. Перед миграцией сохранить текущую закладку командой `pnpm exec wrangler d1 time-travel info <DATABASE>` и записать её в журнал выпуска.
2. Создать отдельный SQL-экспорт командой `pnpm exec wrangler d1 export <DATABASE> --remote --output=<PRIVATE_BACKUP_PATH>`. Хранить его в защищённом месте с ограниченным доступом и сроком хранения, утверждённым владельцем. Зафиксировать SHA-256 и дату.
3. На отдельной тестовой D1 проверить импорт экспорта и основные счётчики таблиц, вход трёх ролей и доступность каталога. Только после успешной пробы считать резервное копирование настроенным.
4. Восстановление действующей D1 через `pnpm exec wrangler d1 time-travel restore <DATABASE> --bookmark=<BOOKMARK>` **перезаписывает рабочие данные**. Перед ним определить момент отката, прекратить записи приложения, сохранить текущую закладку и экспорт, получить решение владельца о потере данных после выбранной точки. Затем выполнить проверку приложения и сверить счётчики.

Cloudflare хранит историю Time Travel до 30 дней на платном плане и до 7 дней на бесплатном. Для более долгого хранения нужен отдельный экспорт вне D1. [Документация Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/), [команды Wrangler](https://developers.cloudflare.com/d1/wrangler-commands/).

Ключ `ESTATEHUB_MFA_ENCRYPTION_KEY` хранится отдельно от БД в секретах окружения и в защищённом хранилище владельца. Без него секреты приложений-аутентификаторов из резервной копии не расшифруются. Ключ не записывать в Git или SQL-экспорт.

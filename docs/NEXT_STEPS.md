# Ближайшие работы EstateHub

## Приоритет владельца: самостоятельный вход и три роли

База уже есть: Cloudflare D1 / SQLite; миграции 0000–0019. Пользователь — запись users без административных назначений, застройщик — membership в организации, суперадмин — platform_role_assignments.SUPERADMIN. Не создавать параллельную базу и не заменять доменную модель одним полем role.

Текущий пакет: логин/пароль, серверные сессии, выход, изоляция ролей, три тестовых аккаунта, удаление административной кнопки из публичного хедера. Приватный внешний доступ Sites сохраняется.

## Очередность после авторизации

1. Сверить фактический код с оригиналом ТЗ v2.0 и составить матрицу критериев приёмки. Проценты из handoff — оценки, не доказательство готовности.
2. Покупатель: пройти каталог → избранное → заявка → переписка → просмотр → бронирование; проверить запреты вторичного рынка и верификацию. Подключить SMS, безопасные документы/KYC и платежи.
3. Застройщик: собственные объекты и квартиры, полная CRM, назначение менеджеров, задачи/SLA, команда и права, импорт, биллинг.
4. Суперадмин: очереди проверок, модерация, управление доступом, финансы/возвраты, аудит, настройки и шаблоны уведомлений.
5. Сквозные критерии: конкурентный резерв, идемпотентные платежи/возвраты, восстановление из резервной копии, RU/UZ/EN, доступность и мобильные сценарии.

База хранит общие данные и связывает действия трёх ролей: одна заявка видна покупателю и назначенному застройщику, проверка — администратору, результат — всем уполномоченным участникам. Наличие базы само по себе не означает готовность роли на 100%.
